The foundational primitive is stated in irrs-kernel/src/lib.rs as: "A directed relation declared from observable information." It is the starting point. It is not derived. It arises from three irreducible characteristics: complexity (observable systems are not reducible to a single variable), change as the only observable constant (what is consistently observable is not a stable object, but change), and bounded domain of analysis (every declaration is bounded; D contains only what has been declared through M). Everything in this specification derives from this primitive.

Task 1 — Minimal Observational Domain

1.1 Scenario

An observer O and a single object P are co-present in an observable region. The observer makes two successive position observations separated by a declared time interval. The observable quantity at each event is the relative displacement between O and P — not P's absolute position, not a coordinate in an external frame. Direction and magnitude are declared from the observation. No reference frame is introduced as an independent primitive. Any coordinate representation is itself a declared mapping through M.

This is the smallest scenario satisfying all three foundational characteristics from irrs-kernel/src/lib.rs: complexity (the observer-object system is not reducible to a single variable), change (the observable quantity changes between observations), and bounded domain (only what is declared through M is in D).

Per irrs-kernel/src/region.rs, all five conditions must be established before topology instantiation. No default substitutes for any missing field.

  2. Observable extents declared. [x_lower, x_upper] with declared unit. Both bounds required; no default.

1.6 Conditions Under Which the Domain Is Incomplete

Admission must be rejected, or the domain is declared incomplete, if any of the following hold:

  • ρ_base or χ₀ not declared by M (no kernel default will be substituted).
  • Observable extents not declared.
  • Interior-locus condition not satisfied (x₁ not strictly interior to [x_lower, x_upper]).
  • Any edge's EdgeProvenance not declared.
  • Any edge's direction basis not declared through M.
  • Any value claimed ObservationallyVerified without a submitted VerificationRecord.
  • Degenerate case x₁ = x₂: A(ι)[e₂] = 0; the change edge carries no information. Admissible, but the domain reports zero observed change — this is a finding, not a failure.
Task 2 — Relational Representation

2.1 The Representation Question

Conventional AI represents inputs as vectors in a learned embedding space, as tokens assigned to a discrete vocabulary, or as activations in a neural network layer. Each introduces structure not in the observable: embedding dimension, vocabulary, learned weight matrices.

The question is: if the only observable primitive is a directed relation and operators are limited to the frozen Kernel V8 operators, what is the representation of the admitted observations — and is it sufficient?

2.2 The A Operator: Extraction

The representation of the admitted domain D is the output of the A operator applied to the declared node field ι:

A(ι)[e] = ι[src(e)] − ι[tgt(e)] // Kernel V8, operators.rs For our minimal topology: A(ι)[e₁] = ι[v₀] − ι[v₁] = x₀ − x₁ // Directed difference from observer to object at t₁. // = −r₁ when x₀ = 0 (declared observer reference). A(ι)[e₂] = ι[v₁] − ι[v₂] = x₁ − x₂ = r₁ − r₂ = −Δr // Directed difference between first and second observations. // Negative of the declared change Δr = r₂ − r₁.

This two-component field [x₀−x₁, x₁−x₂] is the relational representation. It is in edge space, not node space, not an external coordinate space. It captures: (1) the observer-to-object relationship at t₁; (2) the change in the object's relationship between observations.

A is necessary: it is the only operator that maps from node space (observable locus values) to edge space (declared relational differences). Without A, there is no relational representation — only a list of scalars at nodes, which are not relations. Relations are declared differences between loci. A is their extraction operator.

2.3 The B Operator: Propagation

B propagates the edge-level field forward through the declared topology, accumulating successor contributions:

B(g)[e] = g[e] + Σ_{f ∈ succ(e)} g[f] // Kernel V8, operators.rs succ(e) = { f ∈ E : src(f) = tgt(e) } // edges continuing from tgt(e) For our topology: succ(e₁) = { e₂ } // e₂ begins at v₁ = tgt(e₁) succ(e₂) = { } // v₂ has no outgoing edges; B is identity at terminal edge Let g = A(ι): B(A(ι))[e₁] = A(ι)[e₁] + A(ι)[e₂] = (x₀ − x₁) + (x₁ − x₂) = x₀ − x₂ ← total directed range: observer to object at t₂ B(A(ι))[e₂] = A(ι)[e₂] = x₁ − x₂ = −Δr Testable invariant: B(A(ι))[e₁] = x₀ − x₂ is independent of x₁. Proof: (x₀ − x₁) + (x₁ − x₂) = x₀ − x₂ for all x₁. ∎

B is necessary: the relational representation of a multi-step observation is not merely the edge-level differences — it is how those differences propagate through the declared topology. B(A(ι))[e₁] = x₀ − x₂ is the accumulated context: the full directed span from observer to the final object position, derived from the declared chain without independent measurement.

2.4 The R Operator: Coupling

R adds ρ-weighted coupling between edges through the declared adjacency structure:

R(g̃)[e] = g̃[e] + ρ[e]·( Σ_{adj+(e)} g̃ − Σ_{adj−(e)} g̃ ) + cc·(cross-topology) adj+(e) = { f : src(f) = tgt(e) } // edges succeeding e adj−(e) = { f : tgt(f) = src(e) } // edges preceding e For our topology (cc = 0): adj+(e₁) = { e₂ } adj−(e₁) = {} // v₀ has no incoming edges adj+(e₂) = {} adj−(e₂) = { e₁ } // e₁ ends at src(e₂) Let g̃ = B(A(ι)): R(g̃)[e₁] = (x₀ − x₂) + ρ[e₁]·(x₁ − x₂) // Total span is coupled to the local change, weighted by ρ[e₁]. R(g̃)[e₂] = (x₁ − x₂) + ρ[e₂]·(−(x₀ − x₂)) = −Δr − ρ[e₂]·(x₀ − x₂) // Local change is back-coupled to the total span, weighted by ρ[e₂]. ρ[e]: determined from ρ_base, χ₀, and the topology's field values. Form of ρ[e]: OPEN (RhoSaturatingForm §11.2, §18). χ definition for acyclic path topology: OPEN (see §5.7).

R is necessary for coupling: it introduces the ρ-weighted influence of adjacent edges on each other. In the minimal two-observation domain, this captures the relational interaction between the local change (e₂) and the total span (e₁) — the magnitude of Δr influences how the total span is represented, and vice versa, through the declared ρ weighting.

2.5 What Is Not Required

  • Embeddings. The representation A(ι) is already in edge space. No embedding is required.
  • Tokens or vocabulary. Loci and values are declared through M, not assigned from a discrete vocabulary.
  • Learned weights. ρ_base and χ₀ are domain-declared. The operator chain A→B→R is frozen. No weight matrix or gradient update is involved.
  • Softmax or normalization. The R output is not normalized. Its values carry the structure of the declared domain.
  • Persistence operators. A_persistence, B_persistence, R_persistence are not needed at M0. Persistence requires a prior EdgeField from a completed execution. The two-observation domain does not span execution sessions.
  • A new mathematical operator. None is introduced. The existing A, B, R operators are sufficient for relational representation of the declared domain.

2.6 Sufficiency Claim

The relational representation A(ι) is sufficient to capture what was declared: the directed difference from observer to object at t₁, and the directed difference between observations. B extends this to the full span. R introduces the ρ-weighted coupling between these two levels.

Whether this representation is sufficient for AI computation — for pattern recognition, generalization, task-directed output — is not established at M0. That question requires Task 3 (evaluation criteria) and belongs to M1 and beyond, subject to Origin authorization.

The following criteria separate Kernel V8 conformance from functional success. Both must be evaluated independently. Neither implies the other.

Kernel V8 Conformance

  • Every edge has a declared EdgeProvenance
  • Interior-locus condition satisfied: v₁ ∈ tgt(E) ∩ src(E)
  • ρ_base and χ₀ declared; no kernel defaults used
  • Observable extents declared and satisfied
  • RhoMaxSelectionRule surfaced as OPEN

Functional Success

  • A(ι) traces to declared ι and declared topology
  • Result changes if and only if declared inputs change
  • Identical declarations → identical outputs (reproducibility)
  • Undeclared edges: rejected at admission
  • Undeclared node values: rejected; not silently zeroed
  • Results remain within declared domain D
  • Degenerate case A(ι) = 0: reported, not silently accepted
  • ParameterProvenance accurately reflects what has been established

3.1 Criterion 1 — Observable Provenance Preservation

Given declared ι = (x₀, x₁, x₂) and topology (V, E): A(ι)[e₁] must equal x₀ − x₁. No other value is correct. A(ι)[e₂] must equal x₁ − x₂. No other value is correct. Any deviation from these equalities, or any output not traceable to a declared (x₀, x₁, x₂), is a provenance failure.

3.2 Criterion 2 — Sensitivity to Observation Changes

Let ι′ be a new declaration with x₁ replaced by x₁ + δ, x₀ and x₂ unchanged:

A(ι′)[e₁] = x₀ − (x₁ + δ) = A(ι)[e₁] − δ // must change by −δ A(ι′)[e₂] = (x₁ + δ) − x₂ = A(ι)[e₂] + δ // must change by +δ B(A(ι′))[e₁] = x₀ − x₂ = B(A(ι))[e₁] // invariant to x₁ ✓ B(A(ι′))[e₂] = (x₁ + δ) − x₂ = B(A(ι))[e₂] + δ // changes by +δ The invariance of B(A(ι))[e₁] to x₁ is a testable mathematical consequence of the V8 operator definitions applied to this declared topology. Not assumed; derived from the frozen operators.

3.3 Criterion 3 — Reproducibility

The V8 operators A, B, R are deterministic functions of their inputs. Given the same declared ι, ρ_base, χ₀, and topology, the full A→B→R chain must produce identical output on every execution. There is no stochastic element in the frozen operators. Numerical precision: bounded by DETECTION_TOLERANCE = 1e-12.

3.4 Criterion 4 — Rejection of Undeclared Relationships

Test A: Add edge e₃ = (v₀ → v₂) without declaring its EdgeProvenance. Expected: Admission rejected. Test B: Submit node field with ι[v₃] where v₃ ∉ V. Expected: Admission rejected. Test C: Declare ρ_base without χ₀ (or vice versa). Expected: Admission rejected. No default substitution. Test D: Submit e₂ with no declared direction basis. Expected: Admission OPEN or rejected.

3.5 Criterion 5 — Remaining Within Declared Mathematical Scope

Output of A→B→R is a field over E = { e₁, e₂ }. Values are real numbers derived from declared (x₀, x₁, x₂, ρ_base, χ₀). No claim about values outside this domain is permitted. No interpolation between declared loci is authorized. No extrapolation to unlisted observations beyond { t₁, t₂ } is authorized. No inference about a hypothetical third observation is authorized.
Task 4 — Path to Transformation and Attention

4.1 Transformation

In the relational framework, transformation is the computation of a new relational state from a declared prior state through the frozen operator chain. It is what the operators already do: they transform a declared node field ι through A→B→R to produce a coupled relational output in edge space. The R operator is the transformation operator.

To test transformation as an AI computation, the following sequence would be required at a future milestone — not authorized at M0:

  1. Declare an initial relational state. Domain D₁ with node field ι₁ and topology (V₁, E₁). This is the "input."
  2. Apply A→B→R to D₁. Produce R(B(A(ι₁))) — the transformed relational state in edge space over E₁.
  3. Declare a second domain D₂ with node field ι₂. This is the "expected output" — a declared observable the transformation is meant to reproduce or approximate.
  4. Compare. Evaluate |R(B(A(ι₁)))[e] − A(ι₂)[e]| for each e ∈ E. This must use declared observable values, not inferred or interpolated. This is governing authority Rule 7: calculated results must return to comparison with declared observables.

The mathematical path is available now. What is missing at M0 is: a second declared domain D₂, a declared correspondence between the edge spaces of D₁ and D₂, and Origin authorization for a transformation experiment. No new operator is needed.

4.2 Attention

Conventional attention (query/key/value + softmax) selects which inputs contribute most to an output through learned weight matrices and softmax normalization. It introduces structure not in the observable.

In the relational framework, the ρ[e] coupling coefficient in the R operator is the kernel's structural answer to this question. ρ[e] governs the weight with which edge e's value is combined with its adjacent edges in the R output:

ρ[e] = f(ρ_base, χ[e], χ₀) Form of f: OPEN (RhoSaturatingForm §11.2, §18). Illustrative assumed form (not authorized): ρ[e] = ρ_base / (1 + |χ[e]| / χ₀) Low |χ[e]| (near-zero circulation) → ρ[e] ≈ ρ_base (high coupling) High |χ[e]| (strong circulation) → ρ[e] ≈ 0 (suppressed coupling)

This is a relational "attention weight" — not learned, not normalized by softmax, but determined by the declared domain parameters (ρ_base, χ₀) and the topology's intrinsic circulation structure. ρ[e] values differentiate which edges contribute strongly to the R output and which are suppressed.

To test relational attention, the following would be required at a future milestone — not authorized at M0:

  1. Declare a task output T (a target observable at a specific edge or set of edges).
  2. Compute ρ[e] for all edges — requires RhoSaturatingForm to be closed by Origin.
  3. Evaluate the contribution of each edge to R at the task-relevant edges. Edges with high |ρ[e]| in that computation are the "attended" edges.
  4. Confirm the result traces to declared observables.

Two OPEN conditions currently block this: RhoMaxSelectionRule and RhoSaturatingForm. The path is clear; the authorization is not yet in place.

4.3 What Is Not Prescribed

This specification does not prescribe how transformation or attention will be mathematically formalized at M1. The M0 claims are:

  • The existing operators contain the mathematical structure from which transformation and attention can be derived.
  • No new operator needs to be introduced for either function.
  • Both functions require declared domains — not learned parameters — to operate.
  • Both require closing RhoMaxSelectionRule and RhoSaturatingForm before precise computation is possible.
